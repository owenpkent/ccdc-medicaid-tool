# Coverage Compass

Free, open-source, privacy-local web tool that helps disabled Coloradans keep their Medicaid under Colorado's 2027 work-reporting rules. It reads a notice on-device, classifies it against a per-state YAML rule library, explains it in plain English/Spanish, and fills official PDF forms locally. Built with CCDC (Colorado Cross-Disability Coalition). Apache 2.0.

## Key rules
- **Rules are generated, not parsed at runtime.** `rules/co/*.yaml` (advocate-editable) is the source of truth. After editing `letter-types.yaml`, run `npm run gen:rules` to rebuild `web/src/lib/rules.generated.ts`. Never hand-edit that generated file; it is committed and also regenerated by predev/prebuild/pretest.
- **Privacy is enforced by a test, not a promise.** `web/src/privacy-guard.test.ts` fails the build if any `src` file touches `localStorage`/`sessionStorage`/`document.cookie`/`indexedDB`/CacheStorage outside `lib/archive.ts`, if `saveArchive()` is called anywhere but `lib/archive.ts` and `components/FormFill.tsx`, or if tesseract `cacheMethod` is not `"none"` in `lib/ocr.ts` / `lib/extract/scanner.ts`. Route all persistence through `lib/archive.ts`.
- **Zero runtime network.** No server, accounts, telemetry, analytics, error reporting, or third-party fetches, ever. The production CSP pins `connect-src 'self'` (vite.config.ts). Vendor OCR/barcode assets into `public/vendor` via `npm run vendor:ocr` (gitignored, ~27 MB, reproducible from the lockfile); never load them from a CDN. No `eval`. New npm dependencies need review.
- **Never put PII in the repo.** Only blank form templates and anonymized/fictional content. No filled forms, real letters, or real data in fixtures, tests, or screenshots. The demo persona and sample ID are deliberately fictional and tested to stay that way.
- **Form-fill engine invariants** (`web/src/lib/{profile,fill,extract}`, shared with the CDASS Enroll project): keep these modules framework-agnostic; never fabricate signatures; gate attestation checkboxes on unambiguous data only; never flatten output PDFs (they must stay editable); keep the exact-copy smoke test green.
- **Accessibility is a hard gate.** WCAG 2.2 AA. axe-core tests and `eslint-plugin-jsx-a11y` (warnings fail) block PRs. Ship English and Spanish together; Spanish stays flagged as unreviewed in the UI until the YAML `es_reviewed` flag is true (`ES_REVIEWED`).

## Stack & layout
- Vite + React 18 + TypeScript (strict, `noUncheckedIndexedAccess` on); react-aria-components, react-intl; pdf.js, tesseract.js, zxing-wasm, pdf-lib (all client-side, lazy-loaded); vite-plugin-pwa. Deliberately no Tailwind, no router, no state library in v0.1.
- `web/` the app; `web/src/lib/` the engine (rules, deadline, fill, extract, archive); `web/src/components/` UI; `rules/co/` the YAML rule library; `docs/` specs/architecture/privacy/accessibility; `research/` anonymized samples (not published).

## Build, run, test
Run every command from `web/` with Node 22 (pinned in `web/.nvmrc`; the floor is 22.22.2).
- `npm install`, then `npm run dev` (http://localhost:5173). `predev`/`prebuild` auto-run `gen:rules` + `vendor:ocr`.
- `npm run build` runs `tsc --noEmit` then `vite build`. `npm run preview` serves the build.
- `npm run test` (Vitest, includes the axe-core and privacy-guard checks) and `npm run lint` must pass before a PR. CI (`.github/workflows/ci.yml`) runs `npm ci` at the repo root then in `web/`, then lint, test, build.

## Conventions
- Format with `npm run format` (Prettier). Lint is zero-tolerance (`eslint --max-warnings 0`); fix every warning.
- No em dashes anywhere; use periods, colons, commas, or parentheses. User-facing copy targets a 6th-grade reading level.
- Small, focused PRs off `main` with imperative commit subjects. Cite a source (HCPF, CMS, statute, or a named CCDC reviewer) for every rule-library change.

## When to ask
- Anything that changes a privacy or network property, adds a dependency, or touches storage.
- Accessibility-affecting UI, and any Spanish or plain-language copy (needs advocate / native-speaker review).
- Medicaid rule content in `rules/co/` (CCDC advocate/attorney review before merge) and the shared engine's signature/attestation/flatten behavior.
